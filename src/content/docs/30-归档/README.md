# 归档规则

> **30-归档/** 放"现在读会被误导"的内容。其他"读完了但可能还会看"留在原位。

## 归档标准(满足任一即可)

### 1. 内容已过时

- API 文档对应的库/框架版本已被取代
- 工具/服务已停止维护
- 最佳实践已被新方案颠覆(比如 lodash → lodash-es 改造)
- 标准/规范已更新

**例子(候选)**:
- `前端/Javascript/CJS, ESM, Webpack` — CJS+ESM 过渡期的笔记,现在项目几乎全用 ESM,价值衰减
- `前端/React/为啥react没有keep-alive` — React 19 已支持类似机制(Offscreen API),需重新评估

### 2. 已被新文件取代

- 同一主题的更完整/更新的笔记已存在
- 新文件已合并老文件的所有关键信息
- 老文件被 wikilink 引用次数为 0(可通过 `scripts/related.sh` 看反向链接)

**例子(候选)**:
- `前端/Javascript/大文件上传` — 与 `前端/Javascript/常见的问题及解决方案` 有重叠,可考虑合并

### 3. 评估性内容已失效

- `开源项目分析/` 下,项目已死/Stars 暴跌/方向改变
- 当时评估的版本与现在主流版本差异巨大

**例子(候选)**:
- 待评估(目前所有收录的开源项目都还活跃)

## 不归档(但容易误判)

- **读完不再回访的读书笔记**:`Books/编程珠玑.md` 这种——内容本身没过期,只是你不再需要
- **过时的 OS/工具知识**:`CS/OS/Ubuntu/包管理.md` 描述 apt 的笔记——内容仍准确,只是新项目用 Docker
- **个人方法论**:`方法论/面试复习.md`——内容有主观性,但没"过期"
- **历史学习笔记**:哪怕一年没看,内容是当时的真实记录

## 归档操作流程

1. 候选笔记:用 `scripts/related.sh` 看反向链接,引用为 0 的优先考虑
2. 评估:看上述标准,确认是"会误导"还是"只是不常看"
3. 移动:`git mv src/content/docs/原路径.md src/content/docs/30-归档/原名.md`
4. 更新元文件:`AGENTS.md` 改路径示例 / `INDEX.md` 在归档章列入 / `CHANGELOG.md` 追加日志
5. 检查 wikilink:如果原笔记被 `[[wikilink]]` 引用,要么更新链接指向归档位置,要么加 `(已归档)` 标注
