## 一句话结论

SOP 不是「设计」出来的理想流程，而是**对自己做得最好的那次做逆向工程**——把隐性判断显性化，直到一个陌生人照着做也能得到差不多的结果。它的价格来自「特定的人在特定的情境下的真实问题」，不来自通用性。

## 一、两个前置误解

| 误解 | 实际 |
| --- | --- |
| SOP = 写教程 | 教程卖方法：买家要自己完成「理解 → 应用 → 执行」三步，多数人卡在「应用」；SOP 卖的是**已经做好情境映射的流程**，只剩「执行」一步，卡住的人更少、完成率更高 |
| 我的东西没什么值得 SOP 化的 | 作者见过最「不可能值钱」的反而卖出了意外成绩：HR 专员的 AI 简历筛选流程、自媒体运营的 AI 选题分析流程、法律从业者的 AI 合同初审流程。共同点是「他们都觉得自己做的事很普通」 |

**价值来源是「特定」，不是「通用」。「任何人都需要」的 SOP 往往没人买。**

## 二、核心洞察：从最佳实践里「发现」，而不是「设计」

- ❌ **正向设计**：坐下想「正确的流程应该是什么」→ 产出的 SOP **看起来很完整，用起来很困难**，因为里面塞满了「你以为用户能做到、实际上做不到」的步骤
- ✅ **逆向工程**：已经做过很多次 → 有一次做得特别好 → 回看那次**实际**做了什么判断、用了什么提示词 → 整理成别人可重复的格式 → 让不懂的人试 → 修卡点 → 重复到「陌生人也能用出差不多的结果」

**实操入口**：不要问「我应该设计什么流程」，问「**我最近做得最好的那件事是什么？那次我是怎么做的？**」

### 逆向工程五问（原文最有价值的一段，可直接照抄使用）

1. 那次**实际**做了哪些步骤？（不是「我应该做什么」）
2. 每个步骤里，我做了什么**判断**？（「我选了 X 而不是 Y，因为 Z」——把隐性判断显性化）
3. 哪个步骤让这次结果比上一次更好？（定位成功的关键因素）
4. 哪个步骤当时差点犯错、后来怎么避免的？（→ 直接变成 SOP 的防错设计）
5. 如果同事来做这件事，哪个步骤他最可能卡住？（预判使用者障碍，在 SOP 里提前解决）

## 三、什么值得 SOP 化：3 个筛选标准

| 标准 | 判据 | 阈值与做法 |
| --- | --- | --- |
| **高频** | 你做过至少 5 次 | 第 1 次在摸索、2–3 次在改进、4–5 次才开始有「这样做更好」的稳定判断；5 次之前做法还在变，此时的 SOP 化价值有限 |
| **有独特价值** | 你做得比 80% 同行好 | 把「我的做法」和「同行的做法」并排放，能说出 3 个以上「我版本里有、同行版本里没有」的东西；想不出说明还没找到独特点 |
| **有市场** | 有人愿意付费 | 必须做**付费意愿测试**：不是问「你觉得有用吗」（所有人都会说有用），而是问「**这个东西，你愿意花 X 元买吗**」 |

**找独特点的方法**：找一个同领域的朋友，用同样的 AI 工具做同一件事，对比两边结果——「哪里不一样」就是独特点。

## 四、SOP 化的 4 个层次

| 层次 | 名称 | 特征 | 谁能用 |
| --- | --- | --- | --- |
| 1 | 流程记录 | 把步骤写出来 | 只有自己（需要你的专业背景才看得懂） |
| 2 | **决策记录** | 不只记步骤，记录「为什么这样做」 | 同领域的人 —— **关键跃迁** |
| 3 | **AI 化** | 每个步骤配可复制的提示词 | 执行时间大幅压缩 —— **效率跃迁** |
| 4 | **产品化** | 使用说明 + FAQ + 错误处理 + 更新机制 | 陌生人无需你解释即可使用 —— **商业跃迁** |

**大多数人止步于层次 1**：步骤写出来了，但这个东西只有他自己能用。

## 五、完整示范（骨架）

原文用「行业竞品分析报告」工作流演示从 0 到可出售的全过程。层次 2 的决策逻辑长这样——摘两条：

- **为什么只看过去 3 个月**：超过 3 个月的信息，对当前战略决策价值有限
- **为什么选这 5 个维度而不是通用的 8 个**：客户是 B2B SaaS，有 3 个维度在该行业不相关

作者标注的三个关键设计（对结构化任何 AI 辅助流程都通用）：

1. **在收集信息之前先加一个「问题框架」步骤**：「这次分析，客户最想回答的核心问题是什么？」——先有问题，再收集信息，整个分析才聚焦
2. **防幻觉提示词**：所有提示词里加「不确定的数据请标注 `[待核实]`」（起因：AI 曾给出「听起来合理但来源存疑」的数据）
3. **显式标注人工介入节点**：战略意图推断与最终结论**不让 AI 定稿**——「AI 不知道我们的资源、节奏和战略优先级」；AI 输出只当「自己思考的触发器」，不是直接用

**层次 3 的提示词模板格式**（每步一个即插即用块）：`步骤名称 / 适用场景 / 提示词 / 变量说明（中括号标注需替换的变量）/ 质检清单 / 人工介入`。

**层次 4 产品化的 4 件事**：

| 件 | 要点 |
| --- | --- |
| 使用说明 | 不介绍「这个 SOP 是什么」，直接说「第一步做什么」；必须明确写**适合谁 / 不适合谁**；并交代「如果你在 X 步卡住，可能是因为……解决方法是……」 |
| FAQ | 卖出第一版后记录买家问的所有问题；第一版 FAQ 来自「让 3 个熟人试用，记录他们哪里不清楚、哪里卡住」 |
| 错误处理 | 对每个可能出错的步骤写明「如果出现 X，应该这样处理」——降低退款理由，也降低被追问的频率 |
| 更新机制 | 声明有效期：「本 SOP 基于工具的 X 版本，工具重大更新后我会在 N 天内发布更新版本，已购买者免费获取」 |

## 六、找第一个买家：最小验证路径

1. **先了解现状，不报价**：找 5 个人问「这类问题你们现在怎么处理的？有没有觉得麻烦的地方？」——不要先报价，不要问「有没有用」
2. **付费意愿测试**：当对方说「有兴趣看看」后，列出 3 个最重要的组成部分 + 大致定价，问「你觉得这个对你有用吗？这个价格你能接受吗？」——**3 人里有 2 人说「有用，价格可以」即验证通过**
3. **不要等完美**：第一版可以只有层次 3 的 AI 化版本，明说「内测版、会按反馈更新、更新免费」。好处：拿到真实卡点、买家有「共创」参与感、知道层次 4 该重点解决什么

若无人说有用，问题往往出在作者列的这三点：**受众是否清晰 / 价值主张是否具体 / 触达渠道是否匹配**——而不在 SOP 本身。

## 七、定价：从「我值多少」改成「它帮买家省了多少」

- ❌ **成本定价**：「我做这个花了 X 小时，所以值 Y 元」——买家不在乎你花了多少时间
- ✅ **价值定价**：「买家原来解决这个问题要花多少时间/钱？用了我的 SOP 后省了多少？那个节省价值多少？我的定价 = 那个价值的 X%」

作者的自算过程（**其自称的估算，非实测数据**）：初级分析师做一份竞品分析需 3–4 天，日薪按 800 元算 ≈ 2400 元，加修改成本约 3000 元；用 SOP 后半天完成，省时间成本约 2400 元 + 修改成本约 1500 元 ≈ **3900 元**；定价取该价值的 10–15% = 390–585 元，他定 **499 元**。
核对：3900 × 10–15% 的计算无误，499 落在区间内；他写的「ROI = 680%」按 (3900−499)/499 实为 **681.6%**，四舍五入无误。

**价值量级 → 定价区间**（作者经验表，非市场调研）：

| 买家节省/获得的价值 | 定价 | 适合形态 |
| --- | --- | --- |
| 1,000 元以下 | 49–199 元 | 数字工具包 / 模板 |
| 1,000–10,000 元 | 199–999 元 | 完整 SOP 工作流 |
| 10,000–100,000 元 | 999–9,999 元 | 系统化课程 / 陪跑 |
| 100,000 元以上 | 按比例谈判 | 顾问 / 定制服务 |

## 八、SOP 的三种升值方式

1. **质量迭代**：每次买家使用后只问两句——「哪个步骤你觉得最有用？」「哪个步骤你觉得不够清楚或用起来有困难？」→ 版本号 v1.0 → v1.1 → v2.0，已购买者免费获取。作者认为这一动作的口碑价值最高：「买家没想到已经买了的东西还能变更好」
2. **覆盖扩展**：有人问「有没有针对 X 行业的版本？」就是扩展产品线的信号；垂直版可比标准版贵 20–40%（因为更有针对性）
3. **打包升级**：3 个以上相互关联的 SOP → 打包出售（如「完整市场分析系统」= 竞品分析 + 用户访谈整理 + 市场规模估算），买家不必东凑西凑，你的客单价上升

## 九、诚实的预期管理（作者自述）

- SOP 化需要多个「打磨」循环，**第一版一定不够好，这是正常的，不是失败的信号**
- 不是所有 SOP 都能卖得动；区别通常不在 SOP 本身的质量，而在受众是否清晰 / 价值主张是否具体 / 触达渠道是否匹配
- SOP 只是「能力商品化」的**第一步**，目的是验证「有人愿意为我的判断付费」；这个验证带来的认知——你的判断力值在哪、谁最需要它、他们最深的痛点是什么——**比 SOP 本身更有价值**，会引导你走向课程、陪跑、咨询

## 审读：编者按与存疑点

- ⚠️ **开篇数字全部自报、无第三方来源**：99 元 × 首周 300 份 ≈ 2.97 万元；「每份交付 0 分钟（自动发货）」的卖点依赖作者自述，只能当量级感受，不能当基准
- ⚠️ **原文有逻辑互斥处**：开头称「每份的交付我花的时间是 60 分钟」，同一段又写「产品是固定的文件包——买家付钱，自动发送，我不在场」——两种交付模式（人工服务 vs 自动发货）被叠写在同一段里
- ⚠️ **正文残留未替换的占位符**：`【S04文章】`、`【X次】`、`【X周】`——说明此文本身是一份**可复用模板**，且结尾指向作者自己搭好的「Y01 / 02-验证过的方法」知识体系。据此应把它读作**体系型引流件**，而非第三方研究
- ⚠️ **定价区间表是作者经验值**，不是市场调研；同类内容里常见的「月入 X 万」二手案例不构成证据（本次收录时检索到的同赛道公开案例亦有此问题）
- ✅ 真正可迁移的是**流程与问法**（逆向工程五问、四层次判据、付费意愿测试的问句形式），不是那些数字

| Windows Python 环境诊断（windows-python-env，改版 11 次） | 11 | 同上 | 同上 |

**结论：本库的起手点不是层次 0（流程记录），而是层次 3 之后的层次 4。** 三个可直接借用的动作：

1. **交付物形态优势**：Hermes skill 文件本身即「层次 3 + 层次 4」的成熟形态——买家在自己的 Hermes 里 `skill_view` 就能用，不需要另写使用说明文件
2. **「比 80% 同行好」的现成答案**（都是真实事故换来的隐性判断，正是原文要求的独特点）：禁止凭记忆估 GitHub 数字（曾把 12.2 万 Stars 误判为 3–5 千）；路径先核验再读（曾把非知识库目录误判为知识库）；收录前先 grep 查重（同赛道反复分享会攒出两份互相打架的文档）
3. **最垂直、最可卖的候选 =「Windows 上的 AI 编程工具链搭建」**（Python 环境 + 第三方 API 路由 + agent CLI 配置）。理由：该痛点域内调用合计 37 次、中文资料几乎空白、目标人群已在为 API 中转付费（付费习惯现成）
