## 视频流

视频具有如下基本概念

**像素**，描述数字图像的最小单位，即描述图像的一个微小方格，每一个方格都有独立的颜色

**图片**，由众多像素排列而成的数字图像

**分辨率**，描述图片在长宽方向由多少个像素组成

**码率**，单位时间内的传输量或者处理量，通常以 bps（字节/秒）来标识

**帧率**，标识一秒有多少帧数，即一秒有多少张连续的图片。常用的有 24FPS，30FPS，60FPS，120FPS

**颜色空间**，表示颜色的数学模型，通过特定的坐标来表示一种颜色

1.  RGB
2.  YUV
3.  HSV

### 采集

将现实世界的模拟信号或者视频图像转换为数字视频信号

### 处理

### 编码

编码的本质就是压缩视频，减小视频大小，增加存储和传输效率，如果没有编码，初略的算下

```js
// 1080P，RGB，25帧，60分钟
1920 * 1080 * 3 * 25 * 60 * 60; // 约 512GB
```

#### H.264/H.265

H.264，它也被称作 AVC（Advanced Video Coding），由 ITU - T（国际电信联盟电信标准化部门）和 ISO/IEC（国际标准化组织 / 国际电工委员会）共同制定。H.265，又称 HEVC（High Efficiency Video Coding），是 H.264 的继任者

空间冗余：对同一帧（图像）压缩，类似于静态图像压缩
时间冗余：对连续的帧（图像）压缩，连续的帧之间变化可能较小，使用后续帧记录相对前帧的变化
编码冗余：高频率出现的像素分配少字节表示，低频率出现的像素，分配多字节表示
视觉冗余：过滤掉人类不敏感的颜色
知识冗余：根据现有知识和背景可以得到

H.264 有如下帧类型

I 帧：关键帧，I 帧有完整的图像
P 帧：向前参考帧，在压缩和解压时，参考前面已经处理过的帧，即 P 帧记录和前帧的差别
B 帧：双向参考帧，在压缩和解压时，同时需要参考前面的帧和后面的帧。B 帧的压缩效率较高，但是解压是性能消耗也相对较高
IDR 帧：特殊的 I 帧，当遇到 IDR 帧时，清空前面的所有参考帧队列，重新开始

### 传输

#### RTP

RTP（Real-Time Transport Protocol，实时传输协议），基于 UDP 实现。可应用于视频电话，会议

#### RTSP

RTSP（Real-Time Streaming Protocol，实时流协议），其包含传输和控制，可基于 RTP 和 TCP。可应用于摄像头，视频点播等等

#### RTMP

RTMP（Real-Time Messaging Protocol，实时消息传输协议），基于 TCP，延迟较高。可应用于直播推流

#### HSL

HLS（HTTP Live Streaming，HTTP 直播流），基于 HTTP，将视频分为小块，使用 HTTP 分段下载，适合非实时场景。可应用于网页播放
